2. THE LADDER AS IMPLEMENTED
--------------------------------------------------------------------------------
At position i the candidate is n = tables.longest_rgi_prefix_length (text, i).
When n >= 1: RUNG 1 asks the catalog for the WHOLE span's asset
(`span_resolves_whole' -> codepoints_of + has_asset) and, on a hit, emits ONE
emoji segment with the joined key. RUNG 2 splits the span into COMPONENTS - one
base character plus the invisible glue trailing it (VS16, ZWJ, TAG characters
U+E0020..U+E007F) - and, only if EVERY component has an asset of its own, emits
one emoji segment per component; that is where flag pairs land against v2.051
(two letter tiles) and where the England flag becomes one black-flag image over
all seven characters. RUNG 3 appends EXACTLY ONE Note_emoji_degraded covering
the span and then leaves it plain, except that any character which is an emoji
starter with its OWN asset is still lifted into an image (with its trailing
glue). When n = 0 the position is not the head of any RGI sequence, so only the
single-starter test runs and no note is emitted - a character that was never a
sequence is just text. Every emoji segment is emitted through one routine,
`append_emoji', which requires `catalog.has_asset (a_codes)' and stamps
`a_bidi.level (a_start)' on the segment; the PLAIN spans are then the GAPS
between the emoji segments (`with_plain_spans'), so `partition' is true by
construction rather than by bookkeeping.

5. HOW `no_resolvable_single_left_plain' IS DISCHARGED
--------------------------------------------------------------------------------
The clause says: no PLAIN segment may contain a character that is an emoji
starter whose OWN one-codepoint asset this catalog resolves. A character ends up
plain in exactly three places, and each is safe by construction:

  (a) n = 0 (heads no RGI sequence). `append_resolvable_singles' runs over that
      one character and applies literally the clause's own test - starter AND
      has_asset - so anything the clause would forbid is lifted first.
  (b) n = 1 and rung 1 failed. Rung 1 probed exactly <<code (i)>>, so
      has_asset is False for that character. Not resolvable, lawfully plain.
  (c) n >= 2 and rung 3 fired. THIS is the case the task brief singled out.
      Rung 2 is all-or-nothing, so a MIXED sequence - one component with an
      asset, one without - falls through to rung 3. Degrading the whole span
      wholesale would leave the resolvable component inside a PLAIN segment and
      violate the clause. So rung 3 does NOT consume the span wholesale: it
      notes the span ONCE and then walks it character by character with the
      clause's own test, lifting what images and leaving only the rest plain.
      Rungs 1 and 2 leave nothing plain at all, so they are vacuous for the
      clause.

No shipped asset set happens to produce a mixed sequence (Noto v2.051 ships a
PNG for every single emoji character, so every component of an RGI sequence
resolves), which is exactly why the test manufactures one with a selective
injected probe (`probe_only_woman': only emoji_u1f469.png exists). Without that
test the mixed case would have been unexercised - and, before the fix in
section 4, it was ALSO the case that exposed the wrong added postcondition.
