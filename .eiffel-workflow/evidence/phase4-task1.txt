ACCEPTANCE CHECKLIST (tasks.md Task 1)
======================================

[DONE] `open' discharges `open_on_success' and `failure_reported'; `close'
       discharges `closed'. The Phase-1 `Hresult_not_implemented' returns
       disappear - failures now report the REAL HRESULT.
       `open' assigns `is_open := Result' so the equality is structural, not
       incidental. `last_hresult' comes from ssd_last_hr() through the new
       {NONE} guard `non_zero_hresult', which substitutes E_FAIL if the shim
       ever failed without setting a code - so `failure_reported' cannot be
       violated by a silent native regression. The constant
       `Hresult_not_implemented' is KEPT (removing a declared feature would be
       a surface change) but is no longer assigned anywhere; its comment now
       says so.

[DONE] `analyze' discharges `runs_on_success' and `failure_reported'.
       Enforced IN C, at the trust boundary (ISSUE 11): ssd_analyze() resets
       both run tables first, and if AnalyzeScript/AnalyzeBidi return S_OK but
       leave EITHER table empty, the shim converts that into a FAILURE
       (ssd_hr = E_FAIL, both tables re-emptied, return 0). A "success" with
       an unpopulated run table is therefore unreachable from Eiffel.

[DONE] `shape_run' discharges `glyphs_on_success' and `failure_reported'; em
       size is the caller's `a_em_size_pixels' (same-N); `a_analysis' is
       passed through verbatim.
       ssd_shape_run() memcpy's the caller's DWRITE_SCRIPT_ANALYSIS bytes into
       its local `sa' unaltered (a NULL analysis means a zeroed one), passes
       (FLOAT)em straight to GetGlyphPlacements' fontEmSize with no scaling,
       and converts actualGlyphCount == 0 into a FAILURE so `glyph_count >= 1'
       always holds on a True answer.

[DONE] Every index accessor keeps its `in_range' precondition honest against
       the live tables; `bidi_run_level' keeps `non_negative';
       `glyph_count'/`script_run_count'/`bidi_run_count' keep `non_negative'.
       The counts read the live C tables (ssd_script_count / ssd_bidi_count /
       ssd_glyph_count), clamped with `.max (0)' so the postcondition holds
       even before any analysis. Out-of-range C accessors return -1/0 rather
       than reading memory, so a precondition violation cannot become a crash.

[DONE] SINGLE-TRANSLATION-UNIT RULE.
       All 29 `external "C inline use "simple_shaping_dwrite.h""' externals
       live in DWRITE_API and nowhere else. Verified on the clean build:
         $ grep -rl 'simple_shaping_dwrite.h' EIFGENs/simple_shaping_tests/F_code --include=*.c
         EIFGENs/simple_shaping_tests/F_code/C1/dw24.c
       EXACTLY ONE generated translation unit includes the header, so the
       shim's statics and COM objects are one set, not two.
       GDI32_API binds <windows.h> DIRECTLY and deliberately does NOT include
       the shim header (a second include would mint a second, silently
       divergent copy of the state). gdi32.lib links via
       `#pragma comment(lib, "gdi32.lib")' in the header; dwrite.dll loads via
       LoadLibraryW + GetProcAddress. ZERO new DLLs (NFR-004).

[DONE] Shim growth beyond the spike: AnalyzeLineBreakpoints (analyzer slot 6)
       sink + accessors for Task 4's `soft_breaks'.
       The analyzer vtable's slot 6 is now TYPED (it was a void* placeholder),
       ssd_sink_breaks() is REAL (the spike's returned S_OK and dropped the
       data), and ssd_analyze_breaks() zeroes the table, runs the analyzer, and
       converts a short delivery into a failure so "one breakpoint byte per
       UTF-16 unit or nothing" holds. DWRITE_SCRIPT_ANALYSIS bit layout used:
       bits 0-1 breakConditionBefore, 2-3 breakConditionAfter, 4 isWhitespace,
       5 isSoftHyphen - the whitespace assertions in the test prove the layout.
       The script and bidi run tables are LEFT ALONE by the breaks pass, so
       Task 4 can `analyze' once and then ask for the breaks of the same
       string before intersecting them.

[DONE] NEVER-RAISES (NFR-011). Every HRESULT is checked in C. Failures cross
       as False (or default_pointer) + last_hresult, never as an exception, and
       never as a partly-filled table: ssd_analyze, ssd_analyze_breaks and
       ssd_shape_run each reset the table(s) they own on EVERY failure path
       before returning, including the out-of-memory paths a growing buffer can
       hit (a sink that cannot grow returns E_OUTOFMEMORY, which aborts the
       whole analysis rather than truncating it).

[DONE] Tests: a native round-trip test reproducing the spike's measured facts,
       reported as an honest SKIP - never a pass - where `open' fails.
       `LIB_TESTS.test_dwrite_native_round_trip', registered in TEST_APP with
       the new `run_native_test' (the way real tests are registered, NOT as a
       skeletal one). It sets `native_round_trip_ran'; TEST_APP prints PASS
       when it ran and SKIP + `native_skip_reason' when it did not, tallying
       the skip in its own `native_skipped' counter so the Phase-5 skeletal
       count Phase 5 must drive to zero never moves because of a machine's
       capabilities. Every measurement is taken and every handle released
       BEFORE the assertions run, so a failing assertion cannot leak an HFONT,
       an HDC or an IDWriteFontFace.

[DONE] spikes/dwrite/ byte-identical; EIFGENs excluded; clean compile, zero
       warnings. See the proofs below.
