[DONE] UTF-16 BOUNDARY - this class owns the code-point <-> UTF-16 mapping.
       `resolved_levels' does it in four explicit steps:
         1. walk the code points once, recording for each the 0-based index of
            its FIRST UTF-16 unit (a code point above U+FFFF takes two units);
         2. fill the UTF-16 buffer in a second pass (surrogates hand-built);
         3. spread AnalyzeBidi's per-RUN levels over a per-UNIT array;
         4. read ONE level per CODE POINT at its first unit.
       So a surrogate pair lands as ONE code point carrying its run's level.

[DONE] `Direction_auto' = first-strong, computed HERE and installed through the
       new settable paragraph reading direction. HOW IT IS COMPUTED - the method,
       written down as the task requires:

       There is no DWrite facility for P2/P3. DWRITE_READING_DIRECTION has
       exactly two members (LEFT_TO_RIGHT, RIGHT_TO_LEFT);
       IDWriteTextAnalysisSource.GetParagraphReadingDirection must answer one of
       them; and AnalyzeBidi takes the paragraph level as an INPUT and never
       reports one it worked out itself. So the detection is ours, and it is
       DirectWrite-ASSISTED rather than table-driven:

         * P2's scan verbatim: walk code points left to right, skipping
           everything between an isolate initiator (U+2066 LRI, U+2067 RLI,
           U+2068 FSI) and its matching U+2069 PDI. Those four are recognized by
           VALUE, so the skip needs no character-class table.
         * each remaining code point's strong class is asked of DIRECTWRITE
           ITSELF: analyze that ONE code point alone and read the resolved level
           back. In isolation the level is a signature of the bidi class -
             LTR paragraph: L->0, R/AL->1, EN->0 (W7 makes it L behind sos=L),
                            AN->2, neutral/NSM->0
             RTL paragraph: L->2, R/AL->1, EN->2, AN->2, neutral->1
           so level 1 under an LTR paragraph means R or AL at once. The single
           ambiguity left is strong L vs EN, which both read (0, 2). A THIRD
           probe - U+200F RLM followed by the code point, LTR paragraph - breaks
           it: the RLM blocks W7, so EN stays a number and lands at level 2 while
           strong L stays at 0.
         * verdict: first probe = 1 -> strong RTL -> paragraph level 1;
           (0, 2, 0) -> strong LTR -> paragraph level 0; anything else is not
           strong and the scan continues. No strong character at all leaves the
           level at 0, which IS rule P3.
         * cost: one AnalyzeBidi per skipped code point (two for numbers, three
           when the first strong character is L); the scan stops at the first
           strong character, which for real chat text is the first character. The
           probes run BEFORE the paragraph's own analysis, so they never disturb
           it - the shim rebuilds its tables per call.
       Evidence it works: the mapping test asserts Direction_auto on the D-015
       line gives paragraph level 1, and the 396-case conformance sample includes
       ALL 28 of BidiCharacterTest's auto cases.

[DONE] Native failure path degrades per NFR-011, never raises.
       The documented fallback is the ALL-PARAGRAPH-LEVEL result: every code
       point carries the paragraph level (1 for Direction_rtl, 0 for
       Direction_ltr and for Direction_auto, which is P3's answer). It is a
       lawful BIDI_RESULT - it discharges every seam ensure - and it is exactly
       the shape NULL_BIDI_RESOLVER produces, so a headless machine degrades to
       headless behavior. It is taken when `backend_open' is False (dwrite.dll
       missing, or factory/analyzer creation failed) and when `analyze' returns
       False. `resolve' and `reorder' additionally each carry a rescue that falls
       back ONCE and only once - the rescue re-raises on a second failure rather
       than looping - so no exception can cross the seam. The class note says all
       of this, and so does the class-level `never_raises' note tag.

[DONE] `reorder' implements UAX #9 L2 for MIXED levels and discharges every
       clause.
       Algorithm, verbatim from L2: find the highest level and the lowest ODD
       level; for lvl from the highest down to the lowest odd - including
       intermediate levels not present in the text - reverse every maximal run of
       positions whose level is >= lvl. Zero native calls.
         same_count / one_based - Result is make_filled (0, 1, n).
         is_permutation / indices_in_range - the array starts as the identity and
             is only ever reversed in place (`reverse_slice'), which cannot
             introduce or lose a value.
         ltr_identity - all-even means no odd level exists, so no pass runs.
         rtl_reversal (ISSUE 13) - all-odd means every position is >= the lowest
             odd level, so the last pass reverses the whole line.
       NULL_BIDI_RESOLVER was NOT touched.
