ACCEPTANCE CHECKLIST (tasks.md Task 9)
======================================

[DONE] The walk uses the PER-CALL `a_policy' (R11) and nothing captured at
       creation; this class holds no FONT_LIST at all.
       `font_for' reads `a_policy.families_for (...)' and nothing else; the
       class has exactly two creation-time references, `probe' and `registry',
       both facade-lifetime objects (DR-012). Procedure, in order:
         1. probe `a_requested' BY SHAPING through the GLYPH_SHAPER seam -
            `SHAPED_ITEM.is_complete' (i.e. missing_glyph_count = 0) is the
            verdict, which is the G2/D-S05 mechanism;
         2. on a gap, walk `a_policy.families_for (script class)' IN ORDER,
            realizing each candidate through `registry' at the SAME
            (weight, italic, pixel_size) as `a_requested', and take the first
            that shapes complete;
         3. exhaustion returns `a_requested' with is_complete_coverage = False.
       Test evidence: `test_fallback_verdict_cache_is_policy_independent' makes
       the THIRD call under a DIFFERENT FONT_LIST object and gets the same
       answer, which only a per-call walk can do.

[DONE] Discharges never_void, same_pixel_size, same_style, no_silent_drop and
       probes_counted, with probes_performed = the coverage SHAPES actually run.
       same_pixel_size / same_style hold because every candidate is realized
       with `a_requested.weight', `a_requested.is_italic' and
       `a_requested.pixel_size' passed straight into `FONT_REGISTRY.font',
       whose own `identity' ensure pins all three. no_silent_drop holds because
       the chosen font is only ever moved off `a_requested' at the moment the
       completeness flag is set True - one assignment, both together, so the
       False case can only ever carry the requested font. Measured:
       `test_fallback_rescue' asserts pixel_size, weight and is_italic equal
       across the rescue, and the exhaustion test asserts the requested font
       comes back BY REFERENCE.

[DONE] This class NEVER touches SHAPING_STATISTICS.
       There is no reference to it anywhere in the file; the tally rides home
       on FALLBACK_CHOICE.probes_performed for the calling engine to add in
       (R7 amended). Verified: `grep -n SHAPING_STATISTICS
       src/fallback/list_font_fallback.e' finds nothing.

[DONE] Script-class bucketing is by CODE POINT RANGE, never by
       SCRIPT_ITEM.script_code.
       `script_class_of' scans the item's characters through
       `READABLE_STRING_32.code (i)' (a full code point, surrogate pairs
       already collapsed by the itemizer). Buckets: Hebrew U+0590-05FF plus the
       Hebrew half of the Alphabetic Presentation Forms U+FB1D-FB4F; Greek
       U+0370-03FF plus polytonic Greek Extended U+1F00-1FFF; Latin the Latin
       letter blocks (U+0041-005A, U+0061-007A, U+00C0-024F less the two
       mathematical signs, U+1E00-1EFF); symbol the ASCII punctuation/digits,
       Latin-1 punctuation, U+2000-2BFF and the supplementary pictographs
       U+1F000-1FAFF; everything else `other'. A mixed item takes the MOST
       SPECIFIC class present, which is simply the minimum because the
       constants are ordered hebrew(1) < greek(2) < latin(3) < symbol(4) <
       other(5). `test_script_class_of_buckets_by_code_point' asserts all of
       it, including that "A + space + shin" buckets HEBREW while its Latin
       prefix alone buckets latin.

[DONE] Verdict cache: write-once per (script class, family), NOT keyed by
       policy identity, valid across per-call policies for the facade lifetime.
       Key is `<class>|<case-folded family>' (GDI's own family matching is
       case-insensitive, so "segoe ui" and "Segoe UI" must not earn two
       probes). WHAT A VERDICT RECORDS, documented in the class note: one
       BOOLEAN per (script class, family) - True = "shaped this class's item
       with zero missing glyphs", False = "did not" - and False is ALSO the
       answer for a family that is absent on the machine, because a font the
       machine cannot realize as itself covers nothing that can be painted.
       Absence is settled by `FONT_REGISTRY.family_exists' (R1's transient
       GetTextFaceW comparison, itself memoized) BEFORE anything is realized:
       GDI substitutes for an unknown family silently, and the substitute
       WOULD have shaped complete - the walk would have "rescued" the item
       with a face nobody has. An absent family therefore costs NO probe.
       Contracted by `verdicts_only_grow' + `verdict_recorded' +
       `probes_bounded_by_verdicts' (see above).
