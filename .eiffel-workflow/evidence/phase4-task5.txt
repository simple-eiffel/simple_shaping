THE DESIGN DECISION THIS TASK HAD TO MAKE: GLYPH ORDER FOR RTL ITEMS
====================================================================
Task 1's native round trip MEASURED this and it is the crux of the task.
It shaped shalom with isRightToLeft = TRUE and asserted:

    assert_true ("cluster map is the identity over shalom", l_clusters_identity)

i.e. DirectWrite answered the cluster map 0 1 2 3 - ASCENDING - for an RTL
run. DirectWrite delivers glyphs in LOGICAL order for BOTH directions and
leaves visual reordering to the caller (DWRITE_GLYPH_RUN carries bidiLevel for
exactly that reason).

Handed straight through, that map becomes 1 2 3 4, which is non-DECREASING and
VIOLATES the frozen `clusters_monotone_rtl' for any RTL item of 2+ characters.
Three options existed:

  (a) Pass the map through.                  Violates a frozen clause. Rejected.
  (b) Mirror the MAP only, leave the glyphs
      in logical order.                      Satisfies the clause while
                                             `clusters' points at the WRONG
                                             glyph - a contract satisfied by a
                                             lie. Rejected.
  (c) Mirror the glyph, advance and offset
      arrays into VISUAL order (left to
      right on screen) and mirror the map
      with them.                             Both frozen clauses hold AND
                                             `clusters' still names the first
                                             glyph of the character's own
                                             cluster. CHOSEN.

So for an RTL item this class emits visual order; LTR items pass through
untouched. The measured proof is below: the spike's logical-order ids
2945/2932/2925/2933 come back from `shape' as 2933/2925/2932/2945 - the exact
reverse - with cluster map 4 3 2 1.

NULL_GLYPH_SHAPER keeps its glyphs in LOGICAL order with a mirrored map. That
divergence is knowing and is now written in the class note: the double is
metric-predictable, not order-faithful, and no contract distinguishes them.

A cluster map that is NOT non-decreasing is not guessed at. `l_sane' rejects
it and the call degrades through R3, because inventing an order for an answer
no measurement covers is exactly the silent wrong answer this backend exists
to avoid.
