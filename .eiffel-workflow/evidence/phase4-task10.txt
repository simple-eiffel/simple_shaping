ACCEPTANCE CHECKLIST (tasks.md Task 10)
=======================================

[DONE] Greedy accumulate; break ONLY at soft-break positions that are also
       cluster boundaries and NEVER inside an emoji segment (DR-007), the
       breaks arriving as RUN granularity (gate decision 1).
       build_lines walks a_runs in LOGICAL order and appends each run to the
       open line while it fits. A run is NEVER divided: the only decision the
       engine makes is which runs go on which line. DR-007 therefore holds
       STRUCTURALLY, not by re-checking - the facade pre-splits at the
       itemizer's soft breaks (which are cluster boundaries), so a base+niqqud
       cluster shares one GLYPH_RUN and an emoji segment is one atomic
       IMAGE_RUN, and neither can be reached by a break decision.
       The class note now states that contract at the top of the file so the
       next reader cannot mistake it for an accident.

[DONE] R2 hanging whitespace, with fits_within the ONLY fit comparison.
       is_breaking_space_run answers whether a run is entirely breaking space
       (an IMAGE_RUN never is; a run whose range falls outside the text is
       treated as ink rather than trusted). A whitespace run EXTENDS the
       candidate line's trailing-whitespace suffix; an ink run resets it to
       0.0. Both sums are then handed to fits_within, which subtracts the
       suffix - so a line-trailing space rides along on the preceding line and
       counts in that line's width, but never pushes the wrap one word early.
       The trailing sum is passed as trail.min (sum) so fits_within's
       trailing_within precondition cannot be tripped by floating-point
       accumulation order.
       NBSP (00A0), FIGURE SPACE (2007) and NARROW NO-BREAK SPACE (202F) are
       deliberately NOT breaking spaces: they exist to forbid the break this
       predicate would authorize. That exclusion is contracted
       (no_break_space_does_not).

[DONE] A single unbreakable run wider than the width takes its own line,
       flagged is_overflowing; never split.
       When a run is offered to an EMPTY line it is accepted unconditionally
       (nothing may be split). If it does not fit, that line is closed
       immediately with the overflow flag - so the flag is set only for a line
       of exactly one run, which is what SHAPED_LINE's overflow_shape /
       overflow_only_when_unbreakable demands. The flag is set nowhere else.

[DONE] Per finished line, a_reorderer.reorder over the line's run LEVELS gives
       VISUAL order (DR-002).
       visually_ordered collects the line's embedding_levels into an
       ARRAY [NATURAL_8], calls the seam, and stores
       Result [visual] = runs [permutation [visual]] using the permutation's
       own lower/upper. A zero-run line skips the call (there is nothing to
       permute); every other line goes through the seam.

[DONE] Line ascent/height = max over the runs' fonts and boxes, metrics_sane
       held, and an empty line still measures.
       run_ascent / run_descent return the font's TEXTMETRIC ascent/descent
       for a glyph run whose font IS realized, and otherwise split the run's
       own (invariant-positive) height by Default_ascent_ratio = 0.8.
       That second branch is what makes the engine headless: an unrealized
       SHAPING_FONT has NO metrics at all (unrealized_has_no_metrics), and
       SHAPING_FONT.line_height cannot even be called on one (it requires
       is_ready), so a font-metric-only rule would either raise or produce a
       0.0 ascent and violate metrics_sane.
       The line takes the max ascent and the max descent over its runs, and
       height = (ascent + descent) max (the tallest run's own extent). Since
       descent >= 0, ascent <= height holds by construction, and ascent > 0
       because every branch of run_ascent is contracted positive.
       A line of ZERO runs takes ascent = 0.8 * pixel_size and
       height = pixel_size - the layout's own size, exactly the metrics the
       Phase-1 placeholder shipped, so FR-N01/AC-6 consumers see no change.

[DONE] Image-run boxes at LINE HEIGHT (FR-007), square, advance = width.
       SPLIT OF RESPONSIBILITY, documented in the class note and again below
       for Task 11: IMAGE_RUN is an immutable value whose box is fixed by its
       creation precondition (box_positive) and whose box_is_advance ensures
       advance = width. The engine CANNOT size it. The FACADE builds the box
       square at the line height it is laying out at. The engine holds the
       other half up: an image box contributes its FULL height to the line's
       extent, with 0.8 of it above the baseline, so a box built at the line
       height leaves the line exactly that tall instead of growing it (which
       is what a "box sits on the baseline" rule would have done).

[DONE] No_wrap (0) -> exactly one unbounded line.
       A separate branch: every run goes on one line, no fit test is
       evaluated (and fits_within's width_bounded: a_width_pixels > 0
       precondition is therefore never reached with 0), nothing overflows.

[DONE] Empty run list / empty text -> ONE line of count 0 (FR-N01/AC-6).
       With no runs the wrap loop does nothing and the still-open empty line
       is emitted, so at_least_one_line holds. With empty TEXT that line's
       count is 0.

[DONE] Discharges never_void, at_least_one_line, partition:
       lines_partition_text.
       Line source ranges are assigned in a SECOND pass from the accumulated
       run coverage: each line starts where the previous one ended, its count
       is clamped so no line runs past a_text.count, and the LAST line absorbs
       whatever remains. partition therefore holds unconditionally -
       including for a run list that does not tile the paragraph, which the
       precondition does not forbid and a total function may not assume away.

[DONE] Tests: test_wrap_cluster_safety (AC-2) turned REAL, plus five more.
       See the test section below. Skeletal count 7 -> 6.

THE FACADE CONTRACT THIS ENGINE RELIES ON  (for Task 11 - read this first)
==========================================================================
build_lines has no soft-break parameter and gains none (Larry's gate decision
1, 2026-09-02). The facade owes the engine all four of these:

  1. RUNS ARE PRE-SPLIT AT SOFT BREAKS. Before calling build_lines the facade
     splits shaped items into runs at the break opportunities
     SCRIPT_ITEMIZER.soft_breaks reported. Those positions are cluster
     boundaries by construction, so the engine's "break between runs" is
     exactly DR-007's "break only at a soft break that is a cluster
     boundary". A run the facade fails to split is a run the engine will
     never break - it will overflow instead, visibly.
  2. RUNS ARRIVE IN LOGICAL ORDER, COVERING THE PARAGRAPH CONTIGUOUSLY, each
     run's source_start / source_count true of a_text. The engine derives line
     source ranges from that coverage. (It is defensive about the failure - it
     clamps and lets the last line absorb the remainder, so partition still
     holds - but the LINE BOUNDARIES would be wrong.)
  3. AN EMOJI SEGMENT IS ONE IMAGE_RUN, and its BOX IS SIZED BY THE FACADE at
     the line height being laid out (square; box_is_advance then makes the
     advance follow). IMAGE_RUN is immutable, so this is the only place the
     size can be decided. The facade's line height is the primary font's
     ascent + descent at pixel_size - and pixel_size itself when that font did
     not realize, which is the same fallback SIMPLE_SHAPING.line_height owes
     FR-N01.
  4. GLYPH RUNS ARE SHAPED AT THE LAYOUT'S pixel_size. The engine does not
     re-measure and cannot check it; runs_at_layout_size does, as
     SHAPED_LAYOUT.make's precondition, when the facade assembles the layout
     from these lines. The engine's lines satisfy lines_partition_text
     unconditionally, so the only one of SHAPED_LAYOUT.make's two structural
     preconditions the facade still has to earn is the same-N one.

================================
All six are HEADLESS: runs are built through NULL_GLYPH_SHAPER (advance
pixel_size / 2 per character, so a k-character run at 16 px measures exactly
8k px) and reordered by NULL_BIDI_RESOLVER. No native shaping is involved, so
every expected line break below is arithmetic, not whatever this machine's

  test_wrap_cluster_safety  (AC-2, was skeletal)
    Text = ALEF+QAMATS BET+PATAH GIMEL+SHEVA, space, U+1F916, "abc" = 11 code
    points, built from code points so the file's encoding is never on trial.
    Runs (the facade pre-split): [1..6] level 1 = 48 px, [7] space = 8 px,
    [8] IMAGE_RUN 16x16 = 16 px, [9..11] = 24 px.
    At 50 px: 2 lines. 48 + 8 fits because the space HANGS; + 16 does not.
    Line 1 = chars 1..7, line 2 = chars 8..11; the pointed run is still ONE
    run of 6 characters; nothing overflows.
    At 20 px: 4 lines. The 48 px cluster run is wider than the width, so it
    takes its own line FLAGGED and STILL 6 characters - it is not split. The
    8 px space does not overflow (hanging). The 16 px emoji box fits. The
    24 px run overflows. lines_partition_text holds at BOTH widths, and the
    emoji IMAGE_RUN is found on exactly ONE line.

  test_wrap_greedy_fill_to_width
    Five pre-split runs of 32 / 8 / 32 / 8 / 32 px at a 72 px width: four on
    line 1 (chars 1..10, width 80.0 - the trailing space IS in the line and in

    runs_at_layout_size (lines, 16) also asserted.

  test_wrap_hanging_whitespace_rule

    at a 32 px width -> ONE line, measuring 40.0, not overflowing. The same

  test_wrap_no_wrap_is_one_unbounded_line
    No_wrap (0) -> 1 line, all 5 runs, all 14 characters, width 112.0, nothing
    flagged.

  test_wrap_empty_input_is_one_empty_line

  test_wrap_line_is_reordered_visually
