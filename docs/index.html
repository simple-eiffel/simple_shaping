Overview

simple_shaping turns mixed-script paragraph text - Hebrew with niqqud, Greek, Latin, emoji - into cached, contracted, paintable layouts. Glyph runs will be drawn by simple_cairo on win32 font faces; emoji ship as pixel-identical inline Noto PNG boxes (color emoji cannot travel the cairo-win32 glyph path - the split is structural, not stylistic).

layout is a total function: it never raises. Native failures degrade to fallback runs, missing-glyph boxes, or SHAPING_NOTE records. A layout cannot fail - only degrade, observably.

The MVP backend is DirectWrite - IDWriteTextAnalyzer driven from Eiffel through a plain-C COM shim (no C++, no ATL, no import library), a pattern proven end-to-end by the feasibility spike kept in spikes/dwrite/. Uniscribe remains a named alternate slot behind the same seams.

The Four Seams

SeamAnswersMVP effectingHeadless double
BIDI_RESOLVERUAX #9 levels + per-line visual orderDIRECTWRITE_BIDI_RESOLVERNULL_BIDI_RESOLVER
SCRIPT_ITEMIZERThe script × bidi intersection + soft breaksDIRECTWRITE_SCRIPT_ITEMIZERNULL_SCRIPT_ITEMIZER
GLYPH_SHAPERItem + font → glyphs, advances, clustersDIRECTWRITE_GLYPH_SHAPERNULL_GLYPH_SHAPER
FONT_FALLBACKWhich font renders an itemLIST_FONT_FALLBACK (ours, every configuration)NULL_FONT_FALLBACK

Seam postconditions are normative - the cross-backend equivalence oracle. Effectings may strengthen contracts, never weaken them; the bidi conformance harness (full BidiTest.txt at Phase 5) tells real engines apart. Script ids are engine-internal opaque ints - never compared across backends. Emoji never reach the itemizer or the shaper: the segmenter lifts them out after bidi resolution, before itemization, and every IMAGE_RUN is resolved to a real asset.

Quick Start

Installation

<library name="simple_shaping" location="$SIMPLE_EIFFEL/simple_shaping/simple_shaping.ecf"/>

The consumer story

local
    shaper: SIMPLE_SHAPING
    l: SHAPED_LAYOUT
do
    -- once per UI processor:
    create shaper.make ({STRING_32} "assets\noto-emoji\png\128")

    -- per message bubble (measure):
    l := shaper.layout_default (message_text, bubble_inner_width, 14)
    bubble_height := l.total_height + 2 * padding

    -- per paint (cached; zero shaping when unchanged):
    l := shaper.layout_default (message_text, bubble_inner_width, 14)

    -- degradations are data, never exceptions:
    if l.has_notes then
        across l.notes as n loop
            log (n.code_name)
        end
    end
end

Run model: SHAPED_LAYOUT → SHAPED_LINE → SHAPED_RUN, closed over exactly GLYPH_RUN | IMAGE_RUN. Lines hold runs in visual order; layouts are immutable and cached. One facade per SCOOP processor; no separate types in the API.
